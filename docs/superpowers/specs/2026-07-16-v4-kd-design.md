# v4 — Logit Knowledge Distillation (KD) probe — design

**Status:** approved 2026-07-16. Separate track (like v2/v3); locked A/B/C/D ablation
and pinned hypothesis untouched.

## Question

v2 showed data quality moves language modeling but not commonsense reasoning at 275M
(capacity-bound). v2's "distillation" was *data-level* (a Cosmopedia text slice), NOT
logit KD. **Does transferring a larger teacher's full output distribution (logit-level
KD) move reasoning where better data could not?**

## The controlled experiment (vs E1)

E1 = {init Run D, fresh disjoint FineWeb-Edu, 2.1B tokens, **cross-entropy**} → clean
no-op (every metric within 1σ). v4-KD is **identical to E1 except the loss is KD from
TinyLlama-1.1B**. This isolates the KD signal perfectly: any movement vs E1 is the
teacher's distribution and nothing else.

## Config (locked)

| | |
|---|---|
| Student init | Run D `step_22999` (weights-only, opt/loader/step reset — same as v2 probes) |
| Teacher | `TinyLlama/TinyLlama-1.1B-intermediate-step-1431k-3T` — **same Llama-2 vocab (32000, 1:1 logit alignment)**, 4× params (distillation sweet spot), and it is the project baseline |
| Data | Fresh disjoint FineWeb-Edu, 2.1B tokens (E1 protocol; reuse E1 shards if present) |
| Budget | 2000 steps ≈ 2.1B tokens (matches E1/E2/E3) |
| KD loss | `L = (1−α)·CE(student, hard) + α·T²·KL_topk(teacherᵀ ‖ studentᵀ)` |
| KD hyperparams | top-k = 64, α = 0.5, T = 2 |
| Teacher runtime | Online, bf16, `no_grad`, top-k logits per step (no offline logit store — scratch purges) |
| lr_muon | 0.006 (same as all v2 probes) |

## Architecture (keep the locked train path clean)

New module **`tinylm/kd.py`** with its own `run_kd` loop, reusing `train.py` helpers
(`build_optimizers`, `cosine_lr`, `save_checkpoint`/`load_checkpoint`, data iteration,
SIGTERM handling). `train.py`/`model.py` are NOT modified — parallels how `sft.py` was
added for v3.

- `kd_loss(...)` — top-k forward-KL + CE mix, temperature-scaled, chunked for memory
  (same reason `chunked_cross_entropy` exists; full 32000-wide KL on (B·T, V) would OOM).
- `Teacher` wrapper — loads TinyLlama-1.1B via `transformers`, `topk_logits(tokens, k)`.
- `KDConfig` + env overrides (`TINYLM_INIT_FROM`, `TINYLM_SHARD_DIR`, teacher path).
- `configs/v4/run_KD_tinyllama_fwe.yaml`, `scripts/kd_probe_job.sh` (40GB-safe:
  teacher fwd-only bf16, top-k KD, grad-checkpoint on, micro-batch tuned).
- Eval reuses `scripts/eval_tinylm.py` → `results/v4/run_KD_eval.json`.

## Acceptance criteria

- `kd_loss` unit-tested: (1) KL term = 0 when student==teacher; (2) α=0 ⇒ equals
  `chunked_cross_entropy`; (3) α=1 ⇒ pure scaled-KL; (4) top-k gather correct;
  (5) temperature T² scaling; (6) ignore_index masking on the CE part; (7) memory-bounded
  (chunked) — no full (B·T, V) fp32 materialization.
- Teacher loads and returns correctly-shaped top-k logits with the shared vocab.
- First-5-min go/no-go on cluster: loss ~2–3 (not ~10 = weights didn't load), no NaN,
  VRAM fits the drawn A100 (40 or 80GB).
- Full suite stays green; `train.py`/`model.py` unchanged.

## Pre-registered interpretation (committed before results — clean either way)

- **Primary:** does HellaSwag/Winogrande acc_norm move past ~1σ where E1 (CE) did not?
- **Secondary:** LAMBADA ppl vs E1 and Run D (high-confidence positive expected).
- **Reasoning moves** → the exciting upside; the one lever that beat the ceiling.
- **Reasoning flat** → decisive negative: "even a 4×-larger teacher's full output
  distribution can't inject reasoning the 275M can't represent" — hardens the
  capacity-bound thesis and closes the distillation objection. **This is a valid,
  portfolio-grade result, not a failure.**

## Cost

~30–40 GPU-hrs (online KD ~halves throughput), ~3–4 rechained 8h segments. Same order
as the E3-full run.

## Non-goals

No reverse-KL / on-policy KD, no 7B teacher (25× gap risks worse transfer), no offline
logit store. Those are possible v4.1 follow-ups if the probe warrants.
